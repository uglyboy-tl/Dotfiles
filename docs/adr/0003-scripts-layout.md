# 脚本统一放 `scripts/`，不为第三方单独分层

`scripts/`（命令行）、`desktop/scripts/`（桌面）、`rpi/scripts/`（树莓派）三处各自独立，但都用 `glob` 链接到同一个 `~/.local/bin`——脚本属于哪个环境由源文件位置决定，不由 PATH 决定。第三方脚本（当前 2 个）与自研脚本同放 `scripts/`，不另设 `vendor/`；第三方来源靠**文件头署名**与根 README 致谢标注。

## Considered Options

- **统一放 `scripts/`**（采用）：少一个顶层目录、少一组显式链接声明；`scripts/*` 的 glob 对新文件零配置。
- **单独设 `vendor/` 分层**：语义最清晰（自研/第三方一眼可分），但当前只有 2 个第三方文件，撑不起"一个目录 + 逐条链接声明"的维护成本。规模变大（如 5+ 个）时再引入不迟。
- **`scripts/<env>/` 子目录**：能收敛成一处，但现有 `glob: scripts/*` 不递归，要改多级链接，改动大而收益不明显。

## Consequences

`scripts/` 里混有体积较大的第三方脚本（`peon` 约 267KB / 7000 行）。更新第三方时注意 `scripts/update-*` 里硬编码的路径。**若第三方数量增长到分层能省下的人力超过它的成本，应重新评估这条决策。**
